# AI-012: Optimasi training RTX 5070

## Permintaan pengguna

"Maksimal kan aja seluruh performa dari VGA saya untuk training"

Pengguna sebelumnya sudah mengizinkan pengembangan pipeline, training, notebook, logging, commit dan push. Optimasi dibatasi pada runtime pipeline model proyek yang sama. Tidak menambah pretrained weights, tidak mengubah target/evaluasi, tidak melakukan overclock atau mengganti driver.

## Rancangan dan perubahan

- Skill brainstorming digunakan untuk perubahan terbatas pada flow training yang ada, sesuai otorisasi pengguna. Hasil yang diukur adalah throughput update nyata pada train, penggunaan GPU/VRAM/daya/suhu, dan kualitas terpisah melalui development.
- Pemeriksaan awal nvidia-smi saat idle: RTX 5070, 12.227 MiB total, sekitar3.227 MiB desktop, 2%utilisasi,18,67W,45C, power limit250W. Tidak menggambarkan utilisasi saat training. TRAIN-013 pernah peak allocated2,09GiB.
- RUN-156 mengonfirmasi VENV proyek, PyTorch2.14.1+cu130/CUDA13/BF16/capability12.0, disk19,14GiB.
- Runtime attention opsional SDPA dengan is_causal=True dan dropout hanya saat training. Default manual tetap tersedia; bobot/nama tensor/arsitektur checkpoint kompatibel. SDPA mengubah urutan numerik dan sampling dropout, sehingga hasil tidak diklaim bitwise identik.
- AdamW fused, pinned host memory/nonblocking transfer, dan TF32 opsional melalui performance config. BF16 tetap digunakan. Default run lama mempertahankan backend lama bila tidak ada config performance.
- Benchmark terdiri dari isolated child processes, train-only batches, enam warmup dan40update terukur per case. Semua bobot hasil probe dibuang, tidak menjadi model atau quality result. Perbandingan menggabungkan backend/optimizer; tidak mengatribusikan seluruh gain ke satu fitur.
- Telemetry nvidia-smi0,5detik dicatat sebagai data observasi. Memori totalnya mencakup desktop/proses lain; allocated/reserved PyTorch terpisah. Kandidat dipilih berdasarkan targettokens/sec dengan headroom sekurangnya1GiB, bukan mengejar VRAM100%.
- Menahan pertumbuhan batch saat freeVRAM<1,5GiB. Kegagalan probe dicatat, termasuk OOM jika terjadi. Training lanjutan dipisahkan dari probe dan memakai checkpoint/lineage yang terverifikasi.

## Referensi teknis resmi

- [PyTorch SDPA](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention): auto dispatch CUDA backend, dropout_p harus0 saat evaluasi.
- [PyTorch AdamW](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW): fused/foreach tersedia; kecepatan di mesin ini tetap diukur.
