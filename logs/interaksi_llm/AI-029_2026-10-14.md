# AI-029: Source-bound prompt intake and status protocol, 14 October 2026

- Task 4 adds a versioned request draft schema, a fixed local capability catalog, and an intake validator. It accepts factual values only when each value has an exact source span in the original prompt or is explicitly confirmed by the user. Nested fact fields require independent evidence.
- The intake checks prompt character and PagePlan context budgets without truncation. It checks local asset and capability references, required facts, supported page genres and CSS modes, then maps outcomes to stable Indonesian statuses and messages. Raw model and validator errors are not exposed to the user.
- Unsupported capability IDs require an exact prompt quote from the trusted catalog. Unsupported genre or style labels are marked out of scope only when the user actually mentioned the label. If a draft invents an unsupported label, intake asks for clarification instead.
- No natural-language fact extraction model or application UI was added. A ready request is normalized for the existing source-bound generator; intake itself creates no page or file.
- RUN-444 captured a failed negative test because its shared fixture prompt actually contained the supposedly unmentioned label. The fixture was corrected and the status fallback was changed to clarification. RUN-446 passed all 17 intake tests and RUN-447 passed all 42 full-page tests. RUN-431 through RUN-448 preserve design, failures, diagnostics, regressions, and scope checks.
- No dataset, checkpoint, or training artifact was created in Task 4. Task 5 will prepare source-bound targets from train families only while keeping validation and final partitions frozen.
